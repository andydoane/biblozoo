## N7f Read My Verse output-only audit and native implementation

Original `read_my_verse.js` is 6,500+ lines of source-owned activity and recovery logic. On the isolated native app, N1 intentionally blocks WebKit audible `HTMLMediaElement.play()` and browser `AudioContext`: the activity's legacy spoken MP3s, typewriter/keyboard sample bank, negative feedback MP3, generated Unscramble/Tap Order pitches and Verse Crawl soundtrack/ending were therefore not really native. N7f migrates **output ONLY**; there is **no invented Read My Verse microphone/recording path**, and no activity/grade/progress rewrites.

The new `BibloZooNativeReadOutputPlugin` lives in already-compiled `SceneDelegate.swift` and is registered in the exact Audio Test Capacitor bridge. It uses AVAudioPlayer for genuine bundled, fixed-key MP3 samples and multiple simultaneous players (so Verse Crawl's background music, spoken item and finale may overlap) and finite in-RAM WAV tones for source-authored feedback. It never invokes a microphone, saves voice, accepts network/caller file URLs, uses Web/HTML fallback, changes `.soloAmbient` or adds a mix/duck category. It validates every verse against **published** `public/verse_data/<verseId>.json` with matching `verseId`, and only accepts known key/crawl/incorrect files under installed `public/verse_audio` and `public/verse_images` directories; JS clip paths are mapped to IDs, never passed to native as arbitrary URLs. No raw audio is sent through Capacitor.

On native iOS `read_my_verse.js` shadows **its own** `Audio` constructor with `BibloZooNativeReadOutputController.NativeAudio`, without replacing `window.Audio` or editing the original browser/Android constructor. A native proxy exposes the ordinary activity-owned `play()`, `pause()`, `currentTime`, `ended`, `loadedmetadata` and `error` events. Critically, `playClip(started:true)` is **not listened-to completion**: only an actual AVAudioPlayer delegate `ended` event with matching request ID completes a spoken chunk/finale. The media clock progresses from native `AVAudioPlayer.currentTime` events rather than an invented timer. Audio failure, OS interruption or an expired native Crawl ending watchdog triggers the existing Read My Verse recovery/Retry path rather than silently granting progress/score.

The actual Read My Verse **Start** and explicit **Welcome Back / Resume Audio** button claim `.soloAmbient` via `activateFromGesture` subject to iOS arbitration; later animated timers merely use the existing session and **never take priority back from an external AirPods Play**. App inactivity/held switch, lock, real `AVAudioSession.interruptionNotification .began` and media reset invalidate native clips/tones without automatic foreground resumption. Normal Stop/end avoids `.notifyOthersOnDeactivation` so music is not invited to auto-resume at every word.
