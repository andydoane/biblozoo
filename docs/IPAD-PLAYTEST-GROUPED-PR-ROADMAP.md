## Cross-device non-regression gate — mandatory for EVERY IP PR

1. **Before code:** refresh `ios-prep` SHA/open PRs/CI and current source; one short-lived branch → PR targeting `ios-prep`, owner reviews and merges. Every PR (including docs-only) must update the **same canonical** `docs/PROJECT-HANDOFF.md` current block with actual verified merge/CI/device statuses, tested evidence and remaining issues. Update this roadmap and `docs/TESTING.md` for each completed/re-scoped packet. The owner may batch iPad/iPhone **observation**, not GitHub merges or test claims.
2. **iPhone is a hard gate for layout work.** Never consider an iPad visual PASS sufficient: compare iPhone **portrait and landscape** at narrow and typical widths, plus iPad portrait/landscape, safe-area inset, short viewport, long Bible verse/pet name, larger text, reduced motion, and the native packaged app. Keep current iPhone layouts unchanged except the expressly requested copy/actions. Source/CSS/DOM tests should catch incorrect global selectors and overflow. If phone layout degrades, do not merge: constrain the selector/media query or revert.
3. **Automation and hardware must remain separate.** Add specific Node/VM/source or visual-layout checks appropriate to each PR, run existing CI (Node regressions, production Web build, Swift parse/asset/privacy when applicable) and inspect **final exact-head** Actions. Only an actual Apple SDK/Xcode build confirms the native build; only the owner's real iPad/iPhone observation confirms visual proportions, touch, audio and feel. Mark each **NOT TESTED / FAIL / PASS** precisely.
4. **No silent state changes:** Preserve activity-owned audio, actual Welcome Back gesture, pause/resume and game clocks, iOS Silent Mode policy and native AVFoundation-only output, Daily Questions/To-Do one-credit semantics, scores, Bible Bux, pet progress, randomized Zoo eligibility, exit/back navigation, offline Web/PWA/Android and accessible alternatives. No decorative change should invent rewards or resume activity while backgrounded.
5. **Family/privacy safety:** The original production app has **10** Zookeeper profiles and an independent **11**-profile Audio Test app. Keep both owner-held private off-device backups separate; family-v2 export still omits stand-alone Zoo rescue/surprise storage keys. Never upload children's data, reset/import/uninstall or use the experimental bundle identifier as the production one without separate owner authorization. Code PRs never auto-merge to `main`, TestFlight or the App Store.
