## Exact original source and the N7c boundary

The reference is **original `ios-prep`** `flashcards/recording.js` and `flashcards/flashcards.js`, both byte-identical in the experiment through #66. The original Flashcards child-facing flow is Record tap → iOS microphone permission on request → ***real painted 3, 2, 1 countdown*** → reveal challenge and begin capture → Stop / timeout → comparison (normal playback and later Wacky Replay), re-record or continue/grade. Original Web/Android `getUserMedia`, `MediaRecorder`, Blob, WebAudio meter, normal playback and Wacky remain intact. On experimental iOS, N1 prohibits WebAudio and HTML output, so no silent fallback is permitted.

**N7c migrates the actual native RECORD/CAPTURE and in-memory ready-take lifecycle only.** It does NOT yet claim that native normal Play, 16-bar meter or Wacky Replay functions: those are separately planned **N7d** and **N7e**. Until then, the comparison screen must visibly say capture-only and offer **“Continue Without Listening” / “Re-record”**, never a silent **“Play My Recording”** action or false `playbackComplete=true`. This deliberate, temporary UI difference from `ios-prep` prevents children interpreting missing audio as successful playback; it is not intended as final Flashcards parity. The existing grade/verse flow remains reachable via explicit Continue Without Listening.

## Technical scope — one temporary native microphone take

- `ios/App/App/SceneDelegate.swift`: extend existing **exact `com.andydoane.biblozoo.audiotest`-bundle-gated** `BibloZooMicSessionProbePlugin` with `prepareCapture`, `beginCapture`, `finishCapture`, `discardCapture`, `getCaptureState`. No new Swift file/project.pbxproj source registration and no stable app plugin. **N7b DEV mic probe and its own saved session snapshot remain independent of Flashcards capture.**
- The existing `requestPermission` is called only from a genuine Flashcards Record tap. After permission granted, `BibloZooNativeSound.devPrepareForMicrophone` invalidates the warm audio output bank and **awaits its actual serial worker idle acknowledgment** before touching the single shared AVAudioSession.
- `prepareCapture` checks true foreground, granted mic permission, the original native output `.soloAmbient` category, no competing `isOtherAudioPlaying`, and no other active mic/probe. It temporarily uses **the N7b owner-preliminarily-tested candidate** `AVAudioSession.Category.playAndRecord`, `.measurement`, `.defaultToSpeaker`. This category is a **test policy within the separate Audio Test app**, not N7g production final approval. Prep opens no audio tap; the ORIGINAL `runCountdown` must fully paint 3→2→1 *before* `beginCapture` installs the input tap and starts AVAudioEngine.
- `beginCapture`: after original countdown, start a **single input-only AVAudioEngine** and capture mono Float32 frames, never monitoring the mic to the speaker. Each realtime input callback copies finite samples into a small local array, enqueues bounded append work to a **dedicated serial `captureWorker`**, and then discards the temporary callback. The **hard limit is 12,000,000 mono floats (about 46 MiB maximum)**, with an iOS-enforced capture time **1,000–120,000ms** or the smaller original per-verse bound. There are no file writes, AVAudioRecorder, WAV/Blob, upload, Base64 JS payloads or profile/backups.
- **Stop** removes input tap, stops the engine, deactivates with `.notifyOthersOnDeactivation`, and restores the exact previous category/mode/options **without restarting output**. It waits until pending worker input chunks flush, then retains **one** temporarily captured take **in native RAM only** until Re-record, navigation/Exit/Skip or `discardCapture`. Native bridge returns only fixed-schema `ready`, random opaque take ID, frame count, duration and `restored` metadata—not voice data. `ready` means nonzero PCM captured/retained, **not** speaker playback confirmation.
- Hardware task switch/lock, permission loss, UIKit `willResignActive`, audio interruption, media services reset, or actual input route change **stops capture without retaining it** and emits a bounded `biblozooCaptureLifecycle` interruption signal. The Flashcards facade also handles `visibilitychange`/pagehide; a **generation token** ensures a late permission, countdown, Stop or worker callback cannot restart an earlier recording. No restart from Welcome Back. A native watchdog stops the input even if JS stalls; it sends a `completed` event only *after* samples have flushed. Category changes immediately after prep can cause a self-generated route notification; there is a **0.5-second** initial settling guard (same intention as N7b), while later route changes cancel capture.
- `verse_games/shared/native-flashcards-capture-n7c.js`: native-only factory overlay loaded **after** unchanged `flashcards/recording.js` and **before** unchanged Flashcards initialization. Exact N1/native iOS gate; if bridge missing, **fail closed** (no browser MediaRecorder/WebAudio/HTML fallback). It preserves the original `BibloZooRecording.create` API, the exact `beforeStart` countdown callback, original `getLimitMs`, and the `onInterrupted` routing to Flashcards intro.
- `flashcards/flashcards.js`: only the **capture-only conditional** on the existing comparison screen is new. It displays that the voice was captured but playback comes in N7d, hides an unusable Play button and Wacky, keeps Re-record and explicit Continue Without Listening, and does not fake a playback-completed reward. On Web/PWA/Android `captureOnly` is undefined, so original UI logic remains unchanged. No changed verse, grade, scoring, profiles, games, N6 source music or Zoo code.
- **N7b pilot controls remain** separate and can still test a four-second mic level. Flashcards uses the same shared native microphone session owner, with an independent capture snapshot to avoid DEV probe cleanup accidentally restoring Flashcards' live session. Ordinary output remains `.soloAmbient` outside approved temporary input.

## Physical iPhone owner acceptance — essential

**Only after personally merging this N7c PR into `experiment/native-ios-audio`** (never `ios-prep` or main): in dedicated GitHub Desktop experiment checkout **Pull origin → `npm run build && npx cap sync ios && npx cap open ios` → Xcode App scheme on physical iPhone**, standalone `com.andydoane.biblozoo.audiotest`. Apple SDK Swift compilation, permission and real audio hardware can ONLY be tested there. New Node VM + full Swift parser on Linux are not equivalent.

1. In **Flashcards**, choose a verse/difficulty, tap real **Record**. iOS microphone permission should appear only if not previously granted; Deny should show original fallback/continue path, never secretly record. With granted permission, watch the full **3, 2, 1** countdown; mic capture should begin **after** it ends, not before. Challenge must show the real **● Recording** indicator. The original 16-bar meter may be blank until **N7d**; that's expected, not a fake success.
2. Say a short phrase (about 3–5 seconds), tap real **Stop**. The app should leave the challenge for the **comparison** screen, explicitly tell you “Recording captured… native playback arrives in N7d,” and offer **Re-record** and **Continue Without Listening**. **There is deliberately NO Play My Recording or Wacky Replay yet.** The initial take's **frame count** must be nonzero per native test/bridge metadata, not just a timer. We are testing input acquisition/retention, not hearing a recording. Use Continue Without Listening → grade; grade/verse progress should happen only once and not be lost.
3. **Re-record** from comparison: a fresh permission/session handoff and full countdown should work again, replacing the old RAM take. Next leave Flashcards/Menu/Skip: temporary voice buffer must be released, no recording on background/return. Start Flashcards again: no stale take.
4. **Task switch WHILE RECORDING** (the specific evidence missing from N7b): hold the iPhone **App Switcher** long enough to become inactive, or fully switch apps/lock for a few seconds. The recording indicator and microphone permission-use dot must stop, and return must show an **interrupted/try again** state—not the comparison screen with an invented completed take. Neither Home nor plain Welcome Back should start mic capture automatically. Repeat once **during the 3, 2, 1 countdown** and once during **Stop/ready**. A ready take may remain in memory across short app backgrounds until explicit Exit, matching original.
5. **YouTube PiP PAUSED vs STILL PLAYING:** if Apple reports other audio, Flashcards should decline new recording session priority instead of silencing YouTube; pausing PiP should permit a new *explicit* Record tap. Interruption should stop the mic and not cause Zoo punishment. Bluetooth route/mic compatibility is still a separately tested N7g issue; do not claim parity without route evidence.
6. After capture completes or is interrupted, try normal **native DEV star/chomp** or original games through a fresh child **Got It!/Let's go!** tap; sound should work once the recording-capable category is restored to `.soloAmbient`. Recordings must never be uploaded, stored in profile backups or written to a file. If a native restore reports `restored=false` or Xcode shows an engine error, stop and share the displayed/console status rather than assuming the session repaired itself.

**Report for N7d planning:** Does recording start only after the countdown? Does Stop land on capture-only comparison with genuine nonzero frames, can you Re-record/Continue, and do countdown/capture App Switcher interruption and subsequent native sound behave correctly? The key distinction is **“captured” does not mean “played.”** We will only test audible replay when N7d is implemented.

## Automated versus independent gates

`node scripts/validate_native_n7c_flashcards_capture.js` runs the actual native JS facade against the *unchanged original* recording.js, including explicit permission/serial output worker handoff, 3-2-1, bounded begin, Stop/ready, no fake Play/Wacky, denial, missing bridge fail-closed, interruption during countdown and actual capture, background, and watchdog completion. The code-source checks verify in-memory Float32 take buffering, opaque metadata and no file APIs, separate N7b and N7c session snapshots, and explicit UI. All previous N1–N7b regressions, Swift `swiftc -frontend -parse` of **SceneDelegate.swift** and **BibloZooNativeSoundPlugin.swift**, and Production Web build must pass on the final PR HEAD.

**PASS criteria:** Green CI only confirms source/logic; actual iPhone nonempty capture, countdown, cancellation/session teardown and original rewards require the owner's physical test. **N7c is NOT normal recorded audio playback, metering, Wacky DSP or full N7g release acceptance.** N7d normal playback + meter, N7e ten Wacky presets, N7f Read My Verse output, N7g privacy and route regression remain planned.
