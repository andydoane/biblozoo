## Confirmed source-level cause

Existing `verse_games/shared/native-learn-tracks.js` subscribes to early Swift `biblozooAppLifecycle` from `BibloZooNativeSoundPlugin` and sends the activity's `onInterrupted` callback only if **a native clip is currently owned**. During Echo's yellow-text user-repeat interval, or Chunks' short silent gap, `window.BibloZooNativeLearnTracks` has **no active native player**, although `State.echoRunning / State.chunkRunning` remain true and `waitForPausableDelay` advances a JavaScript timer. UIKit can send `active:false` while the App Switcher is half-drawn and WebKit still reports `document.hidden=false`; the existing app-level `visibilitychange` listener may run too late. A later unprimed `learn-part-` playback can be rejected and `failNativeLearnTrack` inserts **Sound isn't ready** and Start into the bottom zone instead of the task-switch recovery. A genuine invalid/missing asset should still retain that error/retry path.

## Implementation

1. **Early independent activity lifecycle observer:** In `app.js`, attach exactly one additional native `BibloZooNativeSound.biblozooAppLifecycle` listener while entering Chunks/Echo. On UIKit **inactive or return-active**, it snapshots any active Chunks/Echo sequence and invokes existing `pauseLearnAudioForInterruption` **even with no native AVAudioPlayer**, then renders the *existing* fixed-position Welcome Back overlay. Multiple UIKit/visibility events are idempotent. Neither callback may start an audio session or playback on foreground. Real `onInterrupted` from an active clip still works as before. A native `interrupted` play result is classified as a recovery event, never a missing-asset inline error.
2. **Preserve the exact quiet stage and time:** Track a transient `nativeLearnQuietCheckpoint` for (a) **`chunk-gap`**, indexed by the *completed* chunk, and (b) **`echo-repeat`**, indexed by the *yellow speaking* chunk. Store actual remaining delay in milliseconds, updated by the existing 50ms pause timer. A task switch cancels old callbacks/generation, preserving that exact stage in `learnAudioInterrupted`. The **real Let's go! tap** starts the existing native prime/recovery and continues the same remaining **silent interval**, not the previous sound or the following clip. When quiet time expires, the ordinary next bundled, allowlisted native `learn-part-` clip plays through Swift AVAudioPlayer as before. Do not double-narrate, skip the child's speaking turn, alter chunk pass count, award Learn credit, or change Yellow/white text phases.
3. **Truthful recovery evidence:** The normal native narration gate clears only on actual native progress/ended. For a **quiet-only checkpoint** there is no sound to verify; the Welcome Back popup can close only after ~30ms+ of **actual foreground, unmuted, same-screen remaining-time progress**, independently tracked as `quietPhaseVerified`. This indicates only that the activity clock resumed, **not** that sound played. Normal native completed events still exclusively authorize next chunk/learning credit. A stalled restart/watchdog remains retryable. No synthetic audio-completion event, fabricated media timeline, WebAudio/HTMLAudio fallback or stray audio activation.
4. **No layout/release changes:** The original `screenChunks/screenEcho` Start/error row remains for a true missing/denied native clip. A task switch instead populates `learnAudioInterrupted` and hides bottom Start via existing UI logic while displaying the same fixed-overlay Welcome Back. No new UI elements, CSS, saved profile fields, recording, microphone permissions, session category/mix/duck options, Zoo Escape/rewards, Wacky D4/C5 or previously accepted game sounds. Web/PWA/Android behavior remains original.
