# N6q.3 — Verse Jam title/mode UI pops, Got It press and between-round source sting

> **Owner-reported physical iPhone findings after [N6q.2 Swift compile PR #61](https://github.com/andydoane/biblozoo/pull/61) merged at `b5ebd7970c066aee3fff42f83323cb87568c1f44` on 2026-11-09.** After merging/pulling and running the app, the owner says Verse Jam is **much better overall**: its **opening and ending word-phrase timing and sound now work**. Three problems remain: **no UI pops** on the title and Choose Your Speed screens; **Got It!** improves launch time but loses the visible depressed button animation and the first audio cue sounds sharp/harsh; **all between-round phrases** still have malformed/overlapping sound, perhaps chord + duplicate note. This N6q.3 PR is a proposed fix; **neither JavaScript checks, Swift parser, Web build, nor merging makes it a human-heard iPhone PASS**. Ghost Writer #59 is **merged but NOT owner-tested**. Accepted baseline remains **12/12 standalone external games and 3/5 Playground** (Verse Typer #55, Scripture Scrub #56, Wheel #57), though **5/5 Playground code slices are merged**.

## Source diagnosis and isolated fixes

1. **Title/Choose Speed UI pops were discarded by navigation.** Verse Jam's `wireUiTapButtons` triggers native UI PCM on `pointerdown`, but `setScreen("mode")` and `setScreen("intro")` called `stopRun()`, discarding the audio bank on the same button click. N6q.3 keeps the 2 preloaded fixed UI-pop samples alive during **intro ↔ mode → headphones** navigation without changing actual gameplay, stopMusic/beat cancellation or ownership. Mode selection still requests full **13-ID Jam native PCM** bank from an explicit real speed-button tap. If the title pop is still cold/pending when speed is selected, pass that exact speed pop index into `prepareFromGesture` to play after its first two UI PCM samples are prepared, **only if still within 350ms of that same tap** (no surprise delayed sounds on unrelated screens). Actual foreground/PiP/background still invalidates the bank; no passive reactivation, browser or HTML fallback.
2. **Got It! pressed animation had no paint time.** Original `.versejam-headphones-button:active` CSS was intact, but the native prewarm made screen replacement too quick for WebKit's touch-depressed state to paint. N6q.3 adds an `.is-pressed` visual class for native click only, with **130ms minimum visible press** before `renderShellGame()`, and a short 75ms transform transition. `beginRun` still initiates required native session work directly on the child's real click if a cold retry is needed. The headphone-button pointerdown UI pop remains excluded so it **cannot tear down the hot full audio bank**.
3. **Harsh initial audio:** N6q.1 warmed all twelve note voices during speed selection, but first `startBeatLoop()` immediately issued `jam-group` stop+prepare before intro. N6q.3 uses `cleanRestart:false` on **fresh native beginRun only**: cancel JS timers and beat generation without stopping an already-idle fully preloaded native note pool. The first native drum/kick has **0.72 headroom** relative to the previously too-high uncompensated PCM output; the original source kick/snare/hat recipes, drum rhythm, beat host timestamps, voice samples and Browser/WebAudio compressor remain unchanged. The exact human-audible balance still needs owner hearing.
4. **Between-round notes doubled by two source paths:** `playRoundTransitionSting()` already emits one pitched note per beat for “speed / it / up” and “feel / that / groove” and a **three-note C–G–C chord at the first “time” beat**. N6q.1 added a second *native* word-note for each displayed word, making identical pitches play together for Speed/Feel and a fourth simultaneous competing note on the Time chord. N6q.3 **keeps the complete source-authored sting** (all six “Time” notes / four notes in other stings, chord, note lengths and original round speed), with bounded 100ms lookahead and Swift AVAudioEngine scheduling. It removes **only** the redundant extra native word-note layer; actual visual words stay aligned to the same beats. **Web/PWA/Android retain the complete original two-layer WebAudio version**, not an accidentally altered soundtrack.

## Tests, protection and rollout

`node scripts/validate_native_verse_jam_ui_phrases_n6q3.js` loads the **real** Verse Jam `setScreen`, Got It button click, drum dispatch, `playRoundTransitionSting`, `showRoundTransition` and native audio controller under Node VM mocked UI/Capacitor. It checks all three between-round phrases **native versus original browser**, the first beat C–G–C with no fourth note, UI PCM pop warm/preserve path, Got It 130ms pressed-state contract, first native kick headroom, and no unauthorized session takeover. Existing N6q/N6q.1 (updated to expect native single authored sting) and all standalone/Playground regression checks remain. The experiment CI also **parses the complete Swift plugin** with `swiftc -frontend -parse` and does a production Web build. These are not a real Apple SDK Swift compilation or physical iPhone acoustic validation.

**Owner test after green final-head CI, personal merge into only `experiment/native-ios-audio`:** GitHub Desktop dedicated experiment checkout → **Pull origin** → `npm run build && npx cap sync ios && npx cap open ios` → Xcode **App** scheme / separate physical-iPhone `com.andydoane.biblozoo.audiotest` app. Keep original stable `ios-prep`, original installed BibloZoo, and all other apps unchanged.

1. **Title UI:** Open Verse Jam from Home. Tap **Start**, **How to Play**, **Close**, **Back**, and **Start** again. Listen for original short UI pops, especially a **first cold launch**. Repeated pops should be immediate; a first cold pop intentionally won't play seconds after you navigated away. Return from speed to title and verify subsequent pops continue.

5. **Critical regressions:** Finish full verse and “Great!” without spontaneous Welcome Back; verify GROOVY scoring, practice/completion exactly once, Menu/Help/mute/Replay/Play Again. Genuine held UIKit App Switcher, full switch/lock and YouTube PiP **PAUSED** and **STILL PLAYING** should show ordinary Welcome Back, with audio only after child's real **Let's go!** tap, no Zoo punishment. Home/Feeding/Learn, 12 accepted standalone and 3 accepted Playground remain usable. **Ghost Writer remains untested** unless owner separately hears it.
