# N1 — Native-only iOS sound-output inventory and isolation

> **Scope:** isolated `com.andydoane.biblozoo.audiotest` Capacitor iOS build on `experiment/native-ios-audio`; **not** the original/stable `ios-prep` app. Reviewed against branch base `8e68e1a3` (merged PR #19), 2026-11-07. This is a **source-level inventory**, not a Swift compile or proof of physical audible output. Read [the living handoff](PROJECT-HANDOFF.md) §§9–10.

## Decision and implementation

The owner chose **AVFoundation-only audible output** for experimental iOS, with temporary missing sound preferable to an ambiguous Web/HTML fallback. Existing JavaScript game logic, rewards, navigation, profile storage and PWA/Android code remain. The first N1 slice blocks WebKit **sound output** globally rather than attempting to migrate every individual sound yet.

`scripts/build.js` injects `verse_games/shared/native-only-ios-output.js` immediately after `<head>` in **every HTML page copied to `dist/`**, including the root app, standalone practice games, Playground pages, developer soundboards/utilities and the privacy page. Injection runs **only when** `capacitor.config.json.appId` equals `com.andydoane.biblozoo.audiotest`; the runtime guard activates only for native Capacitor iOS or the `capacitor:` origin. An ordinary web/PWA/Android page is unchanged even if it serves a built HTML file. The native iOS app requires `npm run build && npx cap sync ios` before Xcode build: source HTML opened directly without the production bundle is **not proof** this gate installed.

In the native-only iOS runtime:

- `window.AudioContext` / `window.webkitAudioContext` are unavailable to later scripts; game effects cannot construct an audible Web Audio graph. Code may still test these names and choose older HTML fallback, but that fallback's `HTMLMediaElement.play()` is deliberately rejected for audio, with no fake playback success. The original constructors are not exported.
- Video picture playback is permitted **muted**, and parsed/dynamically inserted media elements are observed to disable audio autoplay and mute video. Native player output is not intercepted.
- The custom Swift `BibloZooNativeSoundPlugin` remains available for the DEV pet-unlock/star/chomp `AVAudioPlayer` sounds. Only that native bridge can produce sounds. `daily_questions_feed_game.js` selects native automatically in the experimental Classic tester: the obsolete unchecked Web selection is hidden there, but left in old source/VM comparison paths for regression compatibility.
- `navigator.mediaDevices.getUserMedia`, `MediaRecorder`, `MediaStream` and their permission semantics are **not patched**. However, a Web Audio microphone *meter* cannot initialize while `AudioContext` is disabled, and HTML playback of recorded takes is intentionally blocked pending N7. The audio-input/capture policy requires separate testing and migration; do not call recording fully native yet.
- Native session policy, interruption counters, `.soloAmbient`, bridge `preload/play/stop` and native resource packaging are unchanged. The existing `interruption-pending` defect is **not fixed** by this guard. If isolation unexpectedly cannot be installed, it attempts to stop page loading rather than silently permit Web output.

## Important limitations (do not overclaim)

1. **N1 is an output isolation layer, not the completed native architecture.** Some old `new Audio(...)`, HTML-media `load()`, and playback/recovery control paths still exist and might initialize WebKit media metadata or affect iOS session state *without producing sound*. N2 and later activity migrations should retire these dependencies rather than assuming the `interruption-pending` issue is solved.
2. The guard covers HTML files processed through the official `scripts/build.js` pipeline. It does not claim to protect arbitrary cross-origin frames, manually opened source files, or new dynamically generated execution contexts outside that pipeline; future code additions need the same gate or explicit proof of native routing.
3. **Temporary silence, failed narration progression and a missing mic meter are possible in this experiment**; these are unresolved functionality, **not** success. Keep screens navigable and preserve recordings/progress; address owner-specific behavior in N5–N7. Test actual recording before assuming its microphone permissions are unaffected by the global iOS session.
4. Audio state is not speaker audibility: native `preload`/`play` acceptance and read-only interruption counts do not prove a child heard a sound.
5. N1 does not implement any Zoo Escape/ZOO BREAK randomness, does not relax real interruption guards, and makes no public-release claim.

## Validation and owner device checks

Automated validation: `node scripts/validate_native_only_ios_output.js` checks platform gating, blocked Web Audio constructors, rejected HTML audio playback, muted video, untouched `getUserMedia`/`MediaRecorder` and intact native DEV bridge. After `npm run build`, run the validator again to verify the injected guard is the **first script** and resolves to an existing file in every generated HTML page. Existing JS regression and web build checks still apply; only Xcode/physical iPhone can confirm Swift, interruption behavior and actual sound.

On a **physical iPhone**, after pulling the experiment branch, `npm run build && npx cap sync ios && npx cap open ios`, launch **BibloZoo Audio Test** (bundle ID `.audiotest`). Confirm: (a) app/standalone games and navigation still open despite missing output, (b) ordinary UI tap/old Web effects are silent, (c) DEV **Play star / Play chomp** remains genuinely audible as native AVAudioPlayer (or record exact error), (d) Classic tester enters **Native ONLY** without offering a fake Web baseline, and (e) inspect whether `interruption-pending` still appears before/after DEV and Feeding taps; do **not** attribute its cause without evidence. Briefly verify a recording control does not automatically start microphone capture or overwrite a take. The original stable BibloZoo app is the separate Web baseline. Record all failures explicitly in the next handoff update.
