Comparing `ios-prep` and the current experiment shows **both** still use `app.js playPetUnlockPackageSound()` with `new Audio("ui_audio/ui_pet_unlock.mp3")`. The experimental N1 guard intentionally rejects WebKit HTML audio. The sound file **exists and is already independently bundled in the native Xcode Resources** as `ui_pet_unlock.mp3`, mapped to existing Swift `BibloZooNativeSound` ID `pilot-unlock` (a native AVAudioPlayer DEV reference). In the experiment those pages still used shared browser `audioEl.play()`, so N1 denied their sound and exposed the conditional **“🔊 Hear Instructions”** HTML retry button. The button **also exists in stable `ios-prep`**, but normally stays hidden there unless audio failed. Owner asks to remove the broken control in the experimental onboarding and restore the original automatic spoken instruction flow, not to redesign onboarding.

## Changes / native output contract

1. **Pet package:** The *real* Open Box button calls the unchanged package reveal/animation, plus **existing native `pilot-unlock` original MP3** on the same click. `BibloZooNativeSound.activateFromGesture({purpose:"ui"})` is invoked synchronously on that tap, followed by strict `preload({soundId:"pilot-unlock"})` and native `play({soundId:"pilot-unlock",volume:0.55})`. Existing sound ID is fixed in Swift; no new Swift resource, Web Audio/HTMLAudio fallback, synthetic blip, audio-session category or input permission. A short generation/visibility/mute/current-screen cap prevents late replay after lock or leaving; scoped `stop("pilot-unlock")` runs on page Exit, mute and UIKit inactive. The child can still open the box when audio is unavailable; no reward or visual timing depends on native ACK (accepted is not acoustic proof).
2. **Four tutorial pages:** Add **only** `tutorial-page-1` through `tutorial-page-4` to the pre-existing native LearnTracks sound-ID validator and Swift `nativeNarrationURL(for:)` allowlist. Swift loads the already-shipped `public/verse_audio/tutorial_page_<N>.mp3` only, with `1...4` check and no arbitrary filename/URL. Use the existing **AVAudioPlayer native narration** lifecycle, bounded preflight, real ended callback and one-current-narrator owner. The first **Create Zookeeper/Choose Zookeeper** gesture and existing **Next** and **Practice time** gestures call native session primer synchronously so the **next page automatically narrates** as in `ios-prep`; there is no new user-visible play button.
3. **No dead native retry:** The existing `renderZooTodoTutorialAudioRetry` returns an empty string **only in the isolated native-only app**, preserving stable Web/PWA/Android original fallback/markup unchanged. A genuine native refusal leaves readable printed instructions and page Next/Learn actions usable, without secretly playing WebKit audio or falsely marking a page heard. No auto-resume/priority reclaim on foreground or after screen lock. A fresh next-page button is a new explicit native activation gesture. Mute and navigation stop the single owned audio clip and invalidate late callbacks. A page is marked heard **only** when the native owner receives `biblozooNarration(type:"ended")` for that page's request; never from Swift prepare/accepted, promise setup, timers or screen rendering.
4. **Preserve original flow:** Four tutorial page wordings, page numbers, “Next,” “Learn a New Verse,” “Practice the Verse,” profile creation and progress, package poof/bouncing-box reveal, Daily New Pet mission unlock, Zoo statistics, rewards and one-use eligibility are unchanged. The original Web/PWA/Android uses the same `new Audio` unlock and `audioEl` tutorial paths as before. No new recording/mic, AVAudioSession category/mix/duck, RAM voice, Wacky D4/C5 or stored progress fields.
