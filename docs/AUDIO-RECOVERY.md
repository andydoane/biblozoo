N7c awaits fresh actual iPhone test, and N7d output playback/meter, N7e ten Wacky DSP, N7f Read My Verse output, N7g integrated reliability remain separately planned.

**Output-input session boundary:** Only on original Flashcards **Record** tap and granted iOS permission, existing `BibloZooNativeSound.devPrepareForMicrophone()` drains the serial native output worker and resets gesture-activated state. `BibloZooMicSessionProbePlugin.prepareCapture()` then owns a temporary recording-capable **`.playAndRecord/.measurement/.defaultToSpeaker`** session after checking `UIApplication.active`, prior `.soloAmbient`, no other audio, and no active DEV mic probe. N7c has its **own saved category/mode/options** independent of N7b DEV probe so N7b UIKit observers cannot prematurely restore a Flashcards session. Session input is prepared before 3s countdown but actual mic input tap starts **ONLY after** original fully painted Flashcards 3,2,1; no automatic foreground activation. This is an owner-preliminarily-tested Audio Test session candidate, NOT an N7g-approved stable release policy.

**Privacy and real input:** Native Swift `AVAudioEngine.inputNode` captures only mono finite Float32 samples into a dedicated serial `captureWorker` with 1–120s per-verse cap plus a hard **12,000,000-frame (~46 MiB) RAM** cap; no AVAudioRecorder, file, text, raw audio bytes over Capacitor, Blob, backup/profile/media URL, microphone monitor or network call. On Stop, input tap removed, engine stopped, session **deactivated without auto-playing** and prior category/mode/options restored, after pending PCM append blocks flush one opaque in-memory take may remain available until explicit Re-record/Exit/Skip/discard. JS receives only frame count/duration and boolean `ready`, **not audible playback confirmation**; N7d will implement native raw take playback. The native 120-second watchdog ends capture even if JavaScript freezes. A route-change notification during the first 0.5s of the app's own expected category setup is ignored; later route change cancels. Keep N7b DEV probe and Flashcards session snapshots separate.

**Task switching and failure:** Held UIKit App Switcher, full app switch, lock, audio interruption, media services reset or genuine route change **ends an active capture and discards its incomplete take**. Native `biblozooCaptureLifecycle` plus JS `visibilitychange`/pagehide events and monotonic generation tokens prevent old permission/countdown/Stop promises from reviving a microphone, changing a new screen or claiming ready. A plain foreground return, Home or Welcome Back never requests mic permission or resumes capture, and the child must deliberately Record again. If completed take before background, maintain single RAM take until explicit Exit, matching original WebBlob session without persisting it. Session-restore failures must surface as failure, never claim a successful take or restart playback; native output should recover only on a fresh child/DEV sound gesture. Never induce an unrelated Zoo penalty, edit score/progress or bypass N1 WebAudio/HTML output isolation.

**Temporary N7c UI contract vs final Flashcards parity:** The comparison screen **clearly labels capture-only** and displays native PCM frame count; it does NOT present “Play My Recording”/Wacky or fake `playbackComplete`. User can **Re-record or Continue Without Listening** and grade normally, while original browser still has Play and Wacky. N7d will bring audible normal replay and genuine 16-bar meter; N7e restores ten original Wacky presets. Green Node source/VM + full Swift grammar parser + Web build is **not physical microphone content, real Xcode SDK compile, speaker audibility or reliable PiP evidence**; N7c must pass independent owner iPhone countdown, capture/Stop, held App Switcher during actual recording, route category restoration and fresh sound tap. ## Non-negotiable behavior

1. **Only a real recovery probe can establish success.** A successful note, a resumed `AudioContext` state, a native diagnostic snapshot, a tap, animation completion, or a simulated developer result is not sufficient. The owner checks that its actual audio/playback clock advances.
2. **No automatic native activation from foreground or decorative sounds.** The bounded native path is considered only after observed stalled Web Audio, through the existing guarded coordinator. Do not create/resume/replace a context just to play Zoo Escape sounds.
3. **Preserve the existing native category and interruption policy.** The app intentionally retains **`AVAudioSessionCategorySoloAmbient`**; do not change category, mode, or audio-session handling without a deliberate, device-tested design review. Native diagnostics must remain observational; the existing bounded reactivation must not be expanded into a generic auto-recovery loop.
4. **Keep a pending interruption distinct from a failed attempt.** If the native signal still says interruption began / recovery deferred, preserve the current LOCK GATE stage and allow another deliberate attempt. Never escalate Zoo Escape just because iOS has not finished the interruption.
5. **Activity-owned callbacks.** The shared Welcome Back/Zoo Escape controller may display stages and request a recovery, but the owner still pauses physics/audio, checks its own playback, resumes on verified success, and cleans up or navigates on exit. In Verse Launch, local Game Menu, Help and Speed Menu pauses share one pause-aware activity clock with task-switch handling: closing a menu must not resume clock time while Welcome Back still owns the pause, or advance the conveyor/bonus timer behind overlays. This local menu behavior does **not** change the audio recovery gate.
6. **Real gesture and bounded deadlines.** On LOCK GATE, the activity-owned recovery callback must run in the real user gesture; avoid introducing deferred synthetic clicks that break iOS unlock behavior. Timeouts and stale-generation guards prevent loops or delayed state changes after exit.
7. **Respect quiet or microphone activities.** A quiet Daily return may be acknowledgement-only; do not invent an audio test. Learn's Listen/Chunks/Echo recovery must verify advancement of its actual HTML narration position; an independent app UI Web Audio failure must not veto narration. A fulfilled `HTMLMediaElement.play()` alone is insufficient. Flashcards / Read My Verse must never spontaneously begin recording or overwrite a partially completed take.
8. **Do not break gameplay on failure.** Zoo Escape may be silent, and rescue stages must still be interactive. On final failure or early exit, execute the owner cleanup and correct route (including special Daily To-Do returns). Preserve score/progress and avoid duplicate rewards.
9. **Do not credit developer simulations.** The hidden testing harness can force failures or deferred outcomes, but the real recovery owner is still required for success. Simulated rescues must not increase persistent per-Zookeeper rescue statistics.

## Zoo Escape lifecycle in brief

| Phase | Expected action |
| --- | --- |
| Return after an interruption | Show Welcome Back and pause activity-owned gameplay |
| Recovery verified | Dismiss safely and resume same activity/progress |
| First genuine failure | Stage 2: one named pet escapes; rescue it; LOCK GATE retries |
| Second genuine failure | Stage 3: ZOO BREAK, several distinct pets; catch all; final LOCK GATE |

Appearance details can evolve; the audio and state boundaries above must not.

C.2b isolates **only opted-in Classic test rounds**: `playPegTone` deliberately emits no Web Audio collision oscillator while the native preview is actively running. The normal Web Audio **context and advancing clock remain in place**, so the established pause/Welcome Back/Zoo Escape recovery gates are not bypassed. Normal Daily Feeding and unchecked Web Classic still make all original tones and use the original HTML/Web Audio star/chomp effects; Labyrinth, Melody and Bounce are untouched. No native `AVAudioSession` category/mode/active call, Xcode resource, timing, score, progress, microphone or backend fallthrough changes.

The developer badge now reveals a sanitized **native bridge rejection code** (for example `interruption-pending`, `not-preloaded` or `play-denied`) on error, rather than hiding it behind a generic message. This is test-only, no persistent logging or user content. If native star/chomp still fail without peg oscillators, collect both this reason and the existing read-only DEV native state counters. If they succeed, that does not by itself establish why mixed Web/native audio failed; a separate scoped design will be needed for peg beeps. **Do not weaken genuine interruption guards or promote native acceptance to the activity-owned recovery-success gate.** See [TESTING.md](TESTING.md) and the [§10 handoff roadmap](PROJECT-HANDOFF.md); Stage D remains blocked.

### Stage C.2c — Web clock first, then native sound preflight, without changing recovery ownership

Owner's C.2b iPhone report after [PR #16](https://github.com/andydoane/biblozoo/pull/16): even with synthesized Web peg tones muted, Classic Native preview **never played audible native star/chomp** and the bridge reported `interruption-pending`. The DEV panel captured a recognized `.began` notification (**1 began, 0 ended, pending YES, reasonCode=0**, app active). The preview game finished with score 11/7 catches, which does **not** verify any audio. This weakens the hypothesis that actual peg oscillators alone cause the native failure; the current Web Audio **context/session startup** is a remaining possible, **unproven**, contributor.

Stage C.2c changes **only** the iOS Classic Feeding *tester* startup sequence, default unchecked. On the actual user `Got It!` gesture, it calls the existing `resumeFeedAudioContext` synchronously; it **must observe an advancing Web Audio clock before it calls native star/chomp `preload`**. Both resume and clock test have bounded deadlines. A missing/stalled/changed context, missing native bridge, or preflight denial switches to the existing **Web effects before round start**, with an explicit DEV reason label. No in-round backend change or simultaneous native/web star/chomp. The existing C.2b diagnostic-only muted Web peg oscillator remains on **Native** Classic; unchecked Web and other modes are not changed. Neither changing audio-session category/mode nor calling `setActive` is part of this experiment.

The experiment also reads the existing **`BibloZooNativeSound.getDebugState()`** method at fixed boundaries: checkbox selection before Got It!, post-Web clock check, post-native preflight, round start and any native-play rejection. The temporary bottom-right on-screen trace is capped at five records and shows only in-memory interruption counts, pending/last signal and short numeric reason. Reads have 500ms deadlines, do not call `play`, do not activate sessions, do not log user or recording data, and can be delayed relative to actual OS notifications. Do **not** infer causation or human audibility solely from the order or the moving clock. Keep the activity-owned Feeding Web-clock/Welcome Back/Zoo Escape Resume gate intact; re-preflight after actual Resume still follows the existing verified activity path, with no automatic foreground sound.

See [TESTING.md](TESTING.md) and the [§10 handoff roadmap](PROJECT-HANDOFF.md) for the physical iPhone A/B procedure and how to report the phase trace if `interruption-pending` persists. **Stage D remains blocked** until actual repeated audible native effects in gameplay and interruption/Resume have been confirmed.

### Stage C.2d — owner-directed Native-only experiment, **not** Web Audio repair

The owner clarified on November 7, 2026 that the **purpose of `experiment/native-ios-audio` is to discover how to make output genuinely native-only**, not to preserve the old Web fallback inside the Native pilot. In C.2c, iPhone state snapshots showed **zero native interruptions** but the Web-clock probe reported `web-clock-unavailable` and the round was silent after choosing Web fallback, while the independent DEV native **Play star** button still audibly worked. Another attempt had a pending interruption already at checkbox selection. Neither case establishes why iOS produced the earlier interruptions; the Web-clock prerequisite was nevertheless inappropriate to *veto native output* during this test.

**C.2d makes Native-only Classic tester preview a genuinely separate path for Feeding-owned sound:** it defers creating/using Feeding's `AudioContext` and HTML star/chomp objects until an **explicit unchecked Web** round starts, never calls Web resume/clock/preload for a checked Native round, never emits peg oscillators or Web/HTML star/chomp as a fallback, and never changes backend after the checkbox is selected. The two fixed-ID native players (`feed-star`, `feed-chomp`) are the only Feeding effects under test. Peg-beep replacement is a later native sound-design slice; their **intentional silence** does not mean playback has succeeded. Missing native bridge/assets/interruption status makes effects **visibly silent with a reason**, never sounds sourced from Web by surprise. Other app screens can still use Web sounds and require future migration work.

**Native-specific pause/Resume:** on app hide or a long frame gap, Native test game still freezes/stops voices and shows Welcome Back with **Resume/Back**. A true user-tapped Resume invokes **only** native `preload` with a deadline, guarding foreground/stale generations; on rejection it remains paused for retry or exit. It does **not** use the Web clock, activate/replace an AudioContext or trigger Zoo Escape as an **audio-recovery minigame** in this opted-in tester. Regular earned Daily Feeding and the unchecked Web comparison keep the previous activity-owned Web Audio + Zoo Escape contracts and cannot be affected. Keep `AVAudioSessionCategorySoloAmbient`, recording policy and player/category safeguards unchanged.

**Zoo Escape design direction:** The owner would prefer future Zoo Escape and **Zoo Break** occurrences to be occasional enjoyable surprises, **not conditioned on failed audio**, once native output is sufficiently reliable. That is a **future separate gameplay change** requiring its own scope, reward tests, probability/product decision and acceptance. C.2d does **not** add random triggers, alter existing non-native recovery or award extra progress. The Native-only preview simply does not invoke the old audio-repair Zoo Escape minigame; it still offers explicit Resume/Back.

A native bridge `accepted:true`, in-memory interruption state and mere Web-clock changes **are not evidence that the user heard a sound**. See [TESTING.md](TESTING.md) and the [living roadmap §10](PROJECT-HANDOFF.md) for the audible-device test and stopping conditions. Stage D is blocked.
