## Evidence and precise aim

- PR #18 Native-only Classic remained silent after a state snapshot already showed `pending=YES began=1 ended=0` *before* native prepare. DEV panel standalone native star/chomp had been heard in earlier tests, but the source of the pending AVAudioSession event was not proven.
- The owner merged N1 and reports the experimental app behaves as described: its expected nonmigrated sounds are silent rather than falling back to WebKit, and the rest of the tested experience is working as anticipated. This is **not a new detailed N2 interruption trace** and does not by itself prove the prior pending issue was fixed.
- N2's objective is to establish a single native **output-session decision point** for the `.audiotest` app, with explicit tap eligibility, conservative pending-state handling, and in-memory chronological evidence. It is **not** a full native sound engine, not a claim of automatic iOS recovery, and not a public/stable app modification.

## Source and state-machine design

**Swift authority:** `ios/App/App/BibloZooNativeSoundPlugin.swift` remains the single native AVFoundation playback and **native-output activation owner**. It registers `activateFromGesture({ purpose: "dev" | "feeding" })` in addition to the prior fixed-ID `preload`, `play`, `stop`, and read-only `getDebugState`. Only the explicit DEV Play tap or Classic Feeding Got It!/Resume native prepare sequence calls it. Nothing plays on startup, background, foreground, observer callback, or a read-only Inspect tap. The game controller still owns the frozen-round/exit state.

**Legacy recovery isolation:** `ios/App/App/SceneDelegate.swift` keeps `BibloZooAudioSessionRecovery` registered for historical/source compatibility, but its `reactivateAfterClockStall` method immediately returns `legacy-web-recovery-disabled` for the `.audiotest` bundle and cannot call `setActive(true)` there. The separate native diagnostics plugin in `AppDelegate.swift` is read-only; it may observe notifications but cannot activate output. **The sole active native-output session operation in this experimental app is `BibloZooNativeSound.activateFromGesture`.** The stable `ios-prep` and Web/PWA/Android runtime are not modified by this branch.

### Eligibility and outcome table

| Observed condition when the user taps | N2 behavior | Allowed conclusion |
| --- | --- | --- |
| iOS app is active, AVAudioSession category is `.soloAmbient`, no pending `.began`, no media-services reset | Return `ready: true, attempted: false, reason: not-needed`; continue with native MP3 preload | Not a guarantee of sound; player `prepareToPlay()` and `play()` must still succeed |
| Native received an interruption `.began` and **no `.ended`**; the app has not completed an inactive/background → active transition | `ready: false, reason: interruption-pending`; **no** session activation, preload or play | Real interruption remains protected; no timeout-based clearing |
| Native received `.began`, then genuinely left and returned foreground, and a **new** DEV/Got It!/Resume gesture occurs | At most two native `setActive(true)` attempts per foreground period, minimum four seconds apart, only in `.soloAmbient`; if iOS accepts, retire the stale latch, allow a **new** native player prepare; if iOS rejects, retain pending | OS acceptance is **not** evidence that star/chomp was heard; record exact result and real listening |
| A delayed `.began` with `AVAudioSessionInterruptionWasSuspendedKey=true` | Record `interruption-suspended-history` as historical; don't latch it as a new live `.began`; preserve any unrelated earlier pending interruption | Distinguishes iOS suspended history from an active event, without proving audio health |
| `.ended` notification | Clear pending eligibility and record `interruption-ended`; never auto-play | A future tap can prepare native audio; `.ended` itself does not resume gameplay |
| Route change | Stop/dispose the prepared players; record numeric route reason and bounded event; do not auto-resume | Subsequent user-driven prep re-creates native players |
| Media-services lost/reset | Stop/dispose all native players; reset records `mediaResetCount` and sets `needsGestureAfterReset`; later explicit tap may request bounded activation. **No auto-replay.** If iOS changed category, fail with `category-not-soloambient` instead of quietly forcing it | Media-reset support is **incomplete** until owner verifies category recovery policy; do not call this production hardened |
| Different audio category, app not active, invalid purpose, cooldown or attempt limit | Refuse activation with explicit code; preserve players/state and do not fall back to Web | An accurate failure is expected; don't claim playback |

**Safety:** No `setCategory`, `setMode`, `setActive(false)`, background-audio entitlement, auto-restart, microphone permission/capture changes, queued retries, or Web Audio fallback. A successful `setActive(true)` is an operating-system acceptance, not an acoustic test. It remains possible that a genuine, unpaired interruption must stay blocked; this PR intentionally does **not** clear it just because time passed or the UI became foreground.

### Event and diagnostic schema

`getDebugState()` remains read-only and returns the previous fields (`appState`, `pending`, `lastSignal`, `beganCount`, `endedCount`, `suspendedCount`, `lastReasonCode`, etc.) **plus** `foregroundEpoch`, `eventSequence`, `mediaResetCount`, `needsGestureAfterReset`, `lastRouteReasonCode`, `activationAttemptsThisForeground`, `activationAttemptsTotal`, `lastActivationResult`, and a `recentEvents` ring buffer of at most **28** records. Each event is a fixed-type code with increasing `seq`, `elapsedMs` relative to plugin initialization, public `appState`, `foregroundEpoch`, pending boolean, and numeric interruption reason code. No Zookeeper/pet name, verse text, recording/microphone content, advertising ID, raw route device name or persistent telemetry is logged; the data is in-memory and visible only through explicit DEV Inspect.

The DEV Inspect button now shows an abbreviated last-eight-events chronology (`#seq:event-code@elapsedMs`). Inspect makes no audio/activation calls, and no event log implies the hardware rendered a sound. Native call errors are bounded and categorized (e.g. `interruption-pending`, `activation-cooldown`, `foreground-attempt-limit`, `activation-os-rejected`). The Swift activation error code/domain may be returned only to the native caller; no personally identifying fields.

## Physical iPhone acceptance / what to record

Build the isolated `BibloZoo Audio Test` from merged `experiment/native-ios-audio` using fresh `npm run build && npx cap sync ios`. In DEV panel, **Inspect first** on a freshly opened app. Then Play star and chomp and **actually listen**. Inspect again and note `pending`, `lastSignal`, `foregroundEpoch`, attempts, `lastActivationResult`, and the event tail. Open Classic Feeding preview → Got It!, listen for star/chomp (pegs still intentionally silent), and inspect again. If it reports `interruption-pending`, **do not claim that WebKit caused it**; switch to another app, return, tap a DEV sample/Resume once and inspect after the new tap. If needed, wait at least four seconds before a second explicit attempt, not a quick tap loop. Also test repeated foreground/background, route change (headphones/Bluetooth if available), a silent-switch/mute check, Back and profile score preservation. Record an OS-rejected activation code if present. Do not deliberately interrupt calls or microphone capture in a way that loses a real child's recording.

**Pass/fail boundaries:** (1) Swift Xcode build and correct separate bundle identity, (2) genuine DEV sounds heard with only native path enabled, (3) native Classic star/chomp heard or accurately silenced with reason, (4) no phantom or delayed replay, no Web fallback, (5) a coherent trace showing why retries were blocked/allowed, (6) no gameplay/reward/data change. Not all tests can pass until N3/N4 migrate more sounds. If `pending` continues without `.ended`, do not bypass it; N2 follow-up should use the trace and consider a sound-session policy review with owner approval.

## Automation and follow-up limits

Linux GitHub Actions validates static Swift source contracts and runs Node mock bridges/Feeding lifecycle/DEV panel tests. It does **not** compile Swift, run on an iPhone, deliver notifications like the OS, validate a real audio session's category, measure latency, or prove the user heard output. Final CI and owner device observations must be recorded separately in the next handoff update. Proceed to N3 voice pools/native tones only after this safe native session gate has been device characterized; otherwise make a focused N2 follow-up PR.
