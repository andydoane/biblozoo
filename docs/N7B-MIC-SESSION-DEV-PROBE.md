## Actual source baseline and deliberate scope

As inspected for N7a, `ios-prep` and current experimental `flashcards/recording.js`, `flashcards/audio-effects.js`, `flashcards/flashcards.js` and `read_my_verse.js` match byte-for-byte. **Flashcards is the microphone feature**: original Record → explicit microphone permission → 3-second countdown → bounded `MediaRecorder` take → Stop → raw playback / ten Wacky presets, with the original 16-bar zero-feedback mic meter. **Read My Verse does not contain a mic recorder**; its remaining paths are output only. N1 experimental native-only guard **blocks audible Web Audio and HTML media** but intentionally leaves `getUserMedia` and `MediaRecorder` input APIs. None of these user-facing flows are wired to this N7b DEV test.

**N7b asks a narrower Apple-platform question first:** can the separate `com.andydoane.biblozoo.audiotest` app (a) request native microphone permission on a real owner tap, (b) temporarily enter a recording-capable AVAudioSession mode, (c) read live microphone **level only** from RAM without monitor playback/recording, (d) stop/restore on explicit stop, **4-second timer**, real UIKit App Switcher, route loss or audio interruption, and (e) allow the existing output engine to recover only on a **fresh sound tap**? The result and Apple route behavior will determine whether this candidate category is suitable for N7c; **do not treat the category choice as approved production recording architecture before owner feedback.**

## What this PR implements — DEV-only, explicit and bounded

- Adds `BibloZooMicSessionProbePlugin` to **existing** `ios/App/App/SceneDelegate.swift` so Xcode already compiles the file (no missing `project.pbxproj` source registration). Registers via existing `BibloZooDiagnosticsBridgeViewController`. Plugin methods `requestPermission`, `beginProbe`, `endProbe`, `getProbeState` have exact allowlisted names and are **bundle-gated** to `com.andydoane.biblozoo.audiotest`.
- A small **DEV N7b Mic Test** panel appears at the lower left in the *separate* native Audio Test app. **No permission/capture/category change happens during app launch, page load, normal background/foreground return, Inspect or ordinary game taps.** Button 1 **Request Mic Permission** invokes Apple's permission API only on that tap. Denial remains denied until the user changes iOS Settings; no auto retries. `NSMicrophoneUsageDescription` is already present; no entitlement or Info.plist changes.
- Button 2 **Test Mic for 4 Seconds** first calls the **existing sound plugin's DEV stop barrier** `devPrepareForMicrophone` to cancel native playback buffers and wait for the serial output worker to actually idle. It invalidates prior sound readiness, ensuring all later native audio needs a fresh child/DEV activation gesture. This is how the test **coordinates** with the single existing output owner rather than starting an uncoordinated second playback owner. Do this on a quiet **Home** screen; don't run while a game is actively playing.
- After granted permission, foreground `UIApplication`, prior `.soloAmbient`, and **no competing audio** are verified, the DEV test temporarily uses candidate **`.playAndRecord` + `.measurement` + `.defaultToSpeaker`**, then explicitly calls `setActive(true)` from that DEV tap's code path. This is **not a permanent switch of the established output category**, not a Flashcards feature flag, and no automatic activation on OS events. If YouTube PiP is still playing and `isOtherAudioPlaying` reports it, the probe refuses to steal priority (`other-audio-playing`).
- Temporary `AVAudioEngine.inputNode.installTap` computes only a **0–100 sound-level percentage** and increments a count of input buffers. The callback drops PCM after that calculation. No `AVAudioRecorder`, temporary file, Blob, waveform history, microphone-to-speaker connection, `Audio`/WebAudio fallback, analytics, network, copy-to-clipboard or child voice text. **Not a recorded-take test and no recorded voice can be played back.**
- Mic acquisition ends after **at most four seconds** even if the page does nothing; dedicated Stop button and UIKit inactive/background, AVAudioSession interruption/media reset and actual route-change teardown end the tap early. Session deactivates with `.notifyOthersOnDeactivation`, then restores the **previous category, mode and options**. It intentionally **does not call `setActive(true)` to restart sound**: use another real DEV sound tap / a child's explicit Got It! / Let's go! to resume. Route changes during the first 0.5s of deliberate category setup are ignored to avoid mistaking the test's own transition for a cable/headphone unplug; later route changes stop capture.
- The panel's read-only **Inspect** shows permission, actual category/mode, input/output route names, other-audio flag, input buffer count and peak level; a peak above zero when speaking plus buffers means the mic delivered signal. **An accepted native session is not physical sound proof**, and a 0 reading could mean quiet speech, hardware route, permission or capture failure. If restore fails, panel says so; do not proceed to a game without investigating.

## Owner physical iPhone test — the real acceptance gate

After PR review and personal merge **only** into `experiment/native-ios-audio` (stable `ios-prep`, main, original installed BibloZoo app and original browser/PWA/Android untouched): In dedicated GitHub Desktop experiment worktree **Pull origin**, run `npm run build && npx cap sync ios && npx cap open ios`; select **App** Xcode scheme and physical iPhone with bundle `com.andydoane.biblozoo.audiotest`. Linux GitHub checks only parse Swift grammar; **they do not compile UIKit, AVFAudio or Capacitor SDK** or confirm mic access.

1. Open the Audio Test app and go to **Home/quiet screen**. Look for **DEV · N7b Mic Test** at lower left and existing **DEV · Native Audio** at upper right. **Before any tap:** iOS should NOT request mic access, no orange microphone indicator, category should remain the existing `soloAmbient`. Tap **Inspect** and confirm it reports status without prompting or activating anything.
2. Tap **1 · Request Mic Permission**. On a fresh installation, choose **Allow**. Expected **permission=granted**; no mic stream or file is running just because permission was granted. For a denial case, optionally use iOS Settings → BibloZoo Audio Test → Microphone and turn access off; test denial is handled without a fake start. Re-enable in Settings for later testing. The system typically remembers this choice.
3. Stop any sound/music, keep YouTube paused, then tap **2 · Test Mic for 4 Seconds**. Say a word near the microphone. Watch `buffers` grow and `levelPeak` rise above 0 while **mic=ON**. No self-voice should come through speakers. The iOS mic indicator may appear briefly. After **four seconds**, check **mic=off**, **restored=yes**, and category back to `soloAmbient`. Press **Stop / Restore Session** for an early-stop repeat. If `restored=NO`, do NOT continue game testing; report the displayed state and route.
4. Next tap an ordinary **DEV native star/chomp or Melody E4 sound** (top-right panel), or a game's real **Got It!**. It should play normally after its **new explicit activation gesture**, not automatically when the microphone stops. Confirm later Feeding/Learn/Playground still produce their existing owner-accepted audio and are not stuck silent, and no extra Zoo Break/punishment is triggered by the DEV test.
5. While a new 4-second mic test runs, briefly **hold the UIKit App Switcher** or fully switch apps/lock. Probe must stop, never resume on return, mic indicator must disappear and category must restore. Returning via Home/Welcome Back should not silently restart recording, sound or Wacky Replay. Test route removal (e.g., unplug wired headphones), if available; the current pilot deliberately excludes Bluetooth HFP configuration from its proposed session options.
6. Try with **YouTube PiP PAUSED** and again **STILL PLAYING**. Paused PiP may allow the test. While competing PiP audio is actually playing, the session probe should refuse with **`other-audio-playing`** whenever iOS reports competition. **No stealing PiP sound or activating automatically.** Note if iOS reports a different route/competition state than expected. Check speaker, wired headphones and Bluetooth speaker availability in Inspect; Bluetooth microphone routing is **not yet asserted** and requires owner approval of options/mode for N7c.

**Please report:** permission granted/denied result, whether input buffers and peak level increase, whether the four-second auto stop and session restore work, behavior in App Switcher and paused/playing PiP, and whether regular native game sound returns on the next user tap. A brief description of any route displayed is helpful. **Do not send recordings**; this test never saves any. Xcode Debug Console errors are helpful if category or engine start fails.
