## Original behavior used as the reference

Original `ios-prep/flashcards/recording.js` and `flashcards/flashcards.js` were directly reviewed; native experiment preserves the web implementation byte-for-byte:

- A real child **Record** tap acquires mic permission; an actually painted **3, 2, 1** countdown runs, then captured microphone input begins, with a visual **16-bar live volume meter** and no audible mic self-monitoring.
- On **Stop**, the child's exact temporary recorded voice is retained. The comparison screen has **Play My Recording**, with an early Stop Playback/Pause gesture, a **Re-record** option and the original verse/difficulty/grade journey.
- **Successful playback completion** means the recorded take has truly played through, **not** merely that the native bridge accepted a Play request. After listening, **Next** and later Wacky Replay eligibility are handled independently; the original Web effects require actual processed sound start. **N7d deliberately does not unlock native Wacky until N7e**, even after normal playback completes.
- Playback is paused on background and the recording may stay in ephemeral memory if it had **already finished** before task switching. An active microphone recording is instead cancelled on interruption; nothing restarts automatically after foreground/Welcome Back. Original Web/PWA/Android `MediaRecorder`, `AudioContext` meter, `Audio` Blob player and Wacky effects remain untouched.

## Native implementation: same RAM take, no WebAudio or HTML fallback

- Existing N7c `BibloZooMicSessionProbePlugin` remains **exact-bundle-gated** to `com.andydoane.biblozoo.audiotest`. Existing `AVAudioEngine.inputNode.installTap` creates finite mono Float32 frames in a serial `captureWorker`; up to 12,000,000 frames / 120 seconds, one temporary take. **N7d does not add files, speech-as-text, Base64/JS PCM, profile backups, AVAudioRecorder, microphone monitor, upload or server calls.**
- The same serial `captureWorker` computes **one RMS level scaled 0–1 about every 80 milliseconds** from the actual incoming PCM, using the original Web meter's approximate -55dB to 0dB visual range. It only sends `biblozooCaptureLevel` with fixed `captureKey` + finite scalar `level`; no microphone audio bytes. The native-only recorder facade supplies that value through the **existing `recording.readLevel()` API**, so the original **16-bar Flashcards meter UI and animation** work without a second AudioContext, permission call or audio feed to speakers. It stops reading/showing on Stop/inactive.
- `finishCapture` / native 120-second watchdog now retain a random **opaque `takeId`** with the nonzero RAM sample count and original sample rate, returning metadata only after the worker flush. The child taps **Play My Recording**: on that true gesture, a new **AVAudioEngine + AVAudioPlayerNode** renders a PCM copy of that exact RAM take via a normal .soloAmbient output session. It **refuses** other active capture, app inactive, wrong category/invalid ID and Apple-reported competing external audio (for example YouTube PiP STILL PLAYING); doesn't automatically seize external-audio priority.
- The native player calls `scheduleBuffer(…, completionCallbackType: .dataPlayedBack)`. Only its true **`biblozooCapturePlayback(kind:"ended")`** event marks `playbackComplete=true`. A returned `started:true` means scheduling started, **not** proof the child heard anything. Native event carries only `takeId` and `playToken`, no sound samples. **Stop Playback** cancels in-flight worker buffer preparation and stops output immediately, without marking complete or erasing the already recorded take; Play again starts from the beginning as original.
- On real UIKit App Switcher/background, interruption or a changed output route, the playback node is stopped and its session deactivated with `.notifyOthersOnDeactivation`. No automatic foreground replay or new microphone session. The **recorded take remains in RAM** for a fresh Play tap unless user chooses Re-record, Skip, navigation/Exit or Dispose; those destroy the PCM take and invalidate old async playback calls/events. Ordinary games keep their own output worker and current `.soloAmbient` policy; Flashcards' previous microphone session was already restored by N7c.
- The native-only `verse_games/shared/native-flashcards-capture-n7c.js` facade is now N7d-aware; the original browser file is not edited. It never creates Web/HTML output on iOS. Comparison once again renders original **Play My Recording / Stop Playback / Re-record** buttons. **Continue Without Listening** is offered only if actual Play fails (same original fallback), and Next becomes available only after `dataPlayedBack` fires; no fake completion/progress. On native `audio.nativeReplay=true` explicitly guards against showing original **WebAudio Wacky Replay** (N7e still required).
- No changes to child grade/score/verse progress, Zoo outcomes, accepted 12+5 games, Vue? No—this is the existing plain JS/Capacitor UI, or original `ios-prep`, PWA/Android and installed stable BibloZoo bundle.
