# BibloZoo 1.0 — native parental-gate / Capacitor bridge source review

**Reviewed:** November 23, 2026 (US Eastern). Native release branch `ios-prep`, source baseline `b56e837d6faac22ca42529e17208395a1add749c` (merged [PR #205](https://github.com/andydoane/biblozoo/pull/205)). **Scope:** static source review of the first-party native bridge, the normal user-facing routes to protected actions, app configuration and existing regression assertions. **Not:** a device penetration test, Xcode/archive attestation, arbitrary-JavaScript resistance certificate, exhaustive search of every gameplay module, parental math age-suitability approval or Apple App Review outcome.

**Disposition for BibloZoo 1.0:** **No new child-reachable bypass was identified in the inspected normal UI paths. No speculative native hardening PR is recommended now.** The known **JS-to-native trust boundary** remains: several native methods trust the already-gated JavaScript caller rather than independently checking a nonforgeable parent proof. That is a meaningful *conditional* defense-in-depth risk if arbitrary untrusted JavaScript ever executes inside the app's privileged WebView; it is **not evidence that a child can invoke those methods through the shipped UI**. Preserve this limitation and revisit it if the content-loading or threat model changes.

## WebView boundaries and real threat model

- [`capacitor.config.json`](https://github.com/andydoane/biblozoo/blob/b56e837d6faac22ca42529e17208395a1add749c/capacitor.config.json) packages `dist` with production bundle ID `com.andydoane.biblozoo`, **without `server.url` or `server.allowNavigation`**. [`scripts/build.js`](https://github.com/andydoane/biblozoo/blob/b56e837d6faac22ca42529e17208395a1add749c/scripts/build.js) copies local runtime files, injecting native identity into packaged HTML. [`index.html`](https://github.com/andydoane/biblozoo/blob/b56e837d6faac22ca42529e17208395a1add749c/index.html) and [Ghost Writer entrypoint](https://github.com/andydoane/biblozoo/blob/b56e837d6faac22ca42529e17208395a1add749c/verse_playground/ghost_writer/index.html) use bundled scripts; inspected game/playground registries have relative local launch URLs. Production `app.js` does not show the browser-version installation gate. Capacitor's [documented default](https://capacitorjs.com/docs/config) sends external top-level URLs to the outside browser, not the privileged WebView. These are favorable indicators, **not an audit of every dynamic resource or future production archive**.
- **Ordinary child interaction**: follow shipped buttons/links and their JS guards; the reviewed routes require an adult gate for opening outgoing links, making sharable Ghost Writer media, and requesting the first mic/Photos permissions. Settings backups/management are scoped to an active parent visit. No child-facing bypass demonstrated.
- **If arbitrary JS executes inside privileged local WebView** (e.g., future remote content, a new untrusted script, a real injection flaw, or unauthorized remote debugging), that script could call `BibloZooMicSessionProbe.requestFirstPermission`, `BibloZooGhostWriterExport.requestPhotosPermission`, `shareImage`, or `finishVideo({destination:"share"})` without performing the JS math gate. Even when Photos is already authorized, direct `saveImage` could save user-created media; arbitrary JS could also read local profile storage and call browser sharing. A JS-only mathematics challenge is **not an isolation boundary against code executing in its own origin**. Do not invent a reusable, forgeable token and call it native proof.
- **Not observed or proved:** there is no identified route for an ordinary child to run arbitrary JS, navigate a malicious web page inside the privileged WebView, change the production bundle identity, or use Xcode/dev console in the shipping app. This review does **not** prove those are impossible, and it did not simulate compromise or execute a physical device exploit.
- **Conditional remediation trigger:** if a concrete script-execution route or remotely loaded content in the privileged WebView is later found, reassess before release; limit navigation origins and remove the injection path, or move truly sensitive actions behind independently verified native authorization if the real threat requires it. Otherwise, leave proven behavior intact rather than risk destabilizing release-critical sharing/permissions.
