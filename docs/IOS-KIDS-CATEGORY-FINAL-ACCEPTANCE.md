## Focused acceptance checklist — do not mark PASS without an observed result

### A. Kids adult-level challenge review (owner / compliance)

**Source/guideline review — November 23, 2026 (policy rechecked; owner/App Review approval NOT yet obtained).** See [official Kids design examples](https://developer.apple.com/kids/), [App Review Guideline 1.3](https://developer.apple.com/app-store/review/guidelines/#kids-category), and [Guideline 5.1.4](https://developer.apple.com/app-store/review/guidelines/#kids).

- [x] **Actual production challenge inspected at `ios-prep` `42b8d6124549`:** `verse_games/shared/parental-gate.js` generates randomized `A − B + C`: A=20–99, B=10..A−1, C=1–9, result 2–98, and accepts only the exact answer. Max 3 failed answers, new math after each wrong answer, **Not Now** cancellation, single-use approved callback, no permanent token, and fail-closed native identity/lifecycle checks. The source and existing synthetic regression coverage support these implementation properties; **no new device/CI test** was run for this assessment.
- [x] **Current Apple Kids guidance reviewed:** §1.3 requires relevant outside links, purchasing/distractions in gated areas. The [Kids design page](https://developer.apple.com/kids/) requires an **adult-level task**, illustrating a number sequence, shape placement, and adult-knowledge question. Apple offers examples **but no prescribed numeric equation range, difficulty score or automatic seal of approval**. A math example is not a guarantee that arbitrary arithmetic is compliant. §5.1.4 child privacy is independent; a gate is not legal parental consent.
- [x] **Reviewer recommendation documented:** For 1.0, **retain the existing two-step arithmetic challenge** unless the owner or App Review identifies a concrete weakness. It's more involved than some official illustrative examples and is already owner-tested for basic iPhone/iPad usability. **Risk:** a math-confident 6–8-year-old can still solve some questions; e.g. `20 − 19 + 1 = 2`. No gate should be described as childproof or officially Apple-approved, and a source review alone cannot certify that it meets **adult-level** in practice. Do not widen this into unnecessary gameplay/design changes.
- [ ] **Owner product/compliance sign-off and App Review remain open:** Decide whether the existing gate is a sufficiently adult-oriented experience for the planned **Made for Kids 6–8** listing; document the parent-gate rationale for App Review notes. Apple makes the final review decision, not the source scan. If a real difficulty defect or reviewer objection arises, propose a **small, targeted challenge-strengthening PR** with updated tests rather than altering unrelated games.
- [x] **Normal protected-action integrations were reviewed in merged native bridge assessment [#206](https://github.com/andydoane/biblozoo/pull/206):** first-time microphone/Photos OS prompts, Ghost Writer picture/video sharing, parent-only Settings family/profile export/import/reset/delete and outgoing email/credits links follow normal parental gate routes. Scoped source review found no ordinary child-reachable bypass; see [bridge review](IOS-NATIVE-PARENTAL-GATE-BRIDGE-REVIEW.md). Native bridge defense-in-depth and final signed release review remain separate; don't call this a security guarantee.
