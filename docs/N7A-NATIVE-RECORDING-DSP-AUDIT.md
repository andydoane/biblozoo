## 2. The original child-visible Flashcards recording contract

1. Child chooses an existing verse and difficulty, then explicitly taps **Record**. Permission may be requested; denied/unavailable allows a deliberate alternate path, not a silent recording.
2. **Microphone acquired before countdown**, with no captured speech yet; show the source **3, 2, 1** countdown. Only after the real countdown completes does `MediaRecorder.start()` capture. The app may obtain a per-verse limit; **120 seconds** is the default fallback. No auto-record when active again.
3. During capture show **Stop** and 16 visual meter bars. A stalled meter is a meter fault, not proof the recording has failed; never auto-request mic again as a meter recovery trick. No mic monitor to speakers.
4. Stop releases tracks promptly, final data arrives asynchronously. A **nonempty** blob becomes a **ready** recording to play back. An interrupted/cancelled/empty capture does not pretend to be finished, nor lose/overwrite an unrelated child's verse progress.
5. On comparison **Play**, the child must actually hear **their own exact recorded take**. Failure must have explicit retry/continue path; don't increment progress or mark completed from a native `accepted:true` before audible delivery.
6. Wacky Replay uses one selected original preset, may run once per comparison **after processing really begins**, and can be retried if it never starts. Stop/background invalidates callbacks; “Welcome Back” acknowledgment does **not** start recording, replay or a new Wacky preset.
7. **Re-record**, skip/permission denial, exit/menu and navigation dispose temporary media and release mic; no upload, no profile/backup persistence, no third-party analytics/audio dumps. A completed take is not destroyed just because the app briefly backgrounds: original lifecycle pauses its playback and preserves in-memory blob unless active capture is interrupted.
8. **Cross-activity priority:** When recording ends/pauses, downstream Feeding, Learn, standalone games and Playground must still use the one agreed native output coordinator. Do not force output `.soloAmbient` while capturing; design the recording-specific session transition and route restoration explicitly.

Original Wacky UI has **10 official preset IDs**, exactly `squirrel, giant, sleepy, rocket, roller_coaster, ascending, descending, demon, chorus_alien, cave`. Source also defines internal/experimental presets; preserve their source and don't silently delete, expose, or promise native parity without a separate inventory and user-facing policy. Speed changes and pitch changes are distinct DSP axes. The shipped SoundTouch license/dependencies need a separate review before adopting any processor into Swift; do not claim parity merely from labels.

## 3. Sensitive audio-session decision: no silent redesign

Current sound policy is a single, deliberate native AVAudioEngine / AVAudioSession owner for **output**, currently `.soloAmbient` and original child-gesture activation/Welcome Back. **Recording is different.** Before implementing N7b's microphone transaction, explicitly decide (owner review + Mac/Xcode prototype) how to request microphone permission, temporarily configure an appropriate recording-capable session, handle possible competing YouTube PiP/Bluetooth route/voice-processing effects, and restore output **without unexpected audio category change or audio priority steal**. The old `.soloAmbient` must not be blindly imposed during capture; **this N7a PR does not change that category** or define a production capture mode. Do not make two plugins race to own the session or call `setActive(true)` on app foreground. Any native-session adjustment needs physical-device evidence and a separate reviewed PR.

An input/capture API design should use **one generation/request ID** per capture; explicit start/stop/release; bounded error/timeout responses; foreground/permission/route/interruption validity; no stale stream or callback revives an old recording; UI state and 3-second countdown remain in the existing Flashcards controller. Keep recordings ephemeral in RAM or an isolated temporary location with tested cleanup; never log raw bytes or filenames with personal content.
