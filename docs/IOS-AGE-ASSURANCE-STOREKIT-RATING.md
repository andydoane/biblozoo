# BibloZoo — staged native StoreKit app-rating comparison

November 24, 2026. Baseline: merged [#241](https://github.com/andydoane/biblozoo/pull/241), `4ee00467a6dec937178dcf85ff2947fb9a07690f`; [merge CI](https://github.com/andydoane/biblozoo/actions/runs/45469430157) passed. This checkpoint is compile-only, not live integration or a legal opinion.

## Evidence and scope

- [StoreKit AppStore.ageRatingCode](https://developer.apple.com/documentation/storekit/appstore/ageratingcode): async optional integer for the app's current rating, introduced on iOS/iPadOS 26.2; compare against a last known value. Missing data is nil. [Apple Kids developer guidance](https://developer.apple.com/kids/) describes this property separately from In-App Purchase. It is applicable in principle to the paid-upfront app; no IAP or StoreKit transaction purchase/restore API is added. A real paid-upfront production result is not yet verified.
- [Apple staff forum answer, July 2026](https://developer.apple.com/forums/thread/822090): zero is expected in Xcode, sandbox and TestFlight. Apple does not publish a numeric mapping on the property reference. Treat zero conservatively as indeterminate rather than as a production rating or baseline; compare nonzero integers as opaque values for equality only. Never map them to age bands or consent, infer ordering, or substitute a listing-draft value.
- [June 3 Texas update](https://developer.apple.com/news/?id=sg176nne), [age assurance Q&A](https://developer.apple.com/support/age-assurance/), [Texas Chapter 121](https://tcss.legis.texas.gov/resources/BC/htm/BC.121.v3.htm): age-rating changes are a significant-change concern; Apple instructs developers to use its native APIs and server notifications. OS launch blocking on revocation does not establish initial minor consent or prove notification handling unnecessary. The no-backend architecture remains a release decision gate.

## Implementation

`BibloZooAppRatingComparison` is pure logic. Disabled mode -> inactive; canceled -> unavailable; unsupported OS -> unsupportedPlatform; nil/zero current -> unavailable; missing/zero previous -> baselineMissing; equal nonzero -> unchanged; unequal nonzero -> changed. No significance direction, permission or access grant is inferred. Baseline is a caller-supplied optional integer; no persistence, logging, account association or WebView exposure.

`BibloZooAppRatingService.compare(previous:)` is a native, @MainActor, compile-only StoreKit adapter in the existing iOS source. It guards the existing Debug/live flag and exact native bundle identity, cancellation and iOS 26.2 availability, and checks cancellation after awaiting StoreKit. Ordinary builds compile but cannot execute the reader; fixture mode cannot execute it. It has no runtime caller, so no additional Apple system request, prompt, gating or UI change. No changes to signing, deployment target, existing app features, PWA, Audio Test, profiles, microphone or backups.

A changed result is merely a candidate input to a future reviewed version-specific significant-update flow. An unchanged result is not proof there are no other significant changes; a missing baseline is not a first-release decision. Do not make up a baseline, persist consent, overwrite an approved baseline before resolving a pending change, or call PermissionKit automatically. Baseline provenance, scope (including storefront/account transitions), persistence/backup policy, first release vs updates, delayed/cancelled permission recovery and any foreground ticket association must be reviewed before a runtime caller is added. No new backend, iCloud, recurring cost or enrollment.
